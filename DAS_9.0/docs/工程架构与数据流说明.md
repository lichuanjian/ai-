# DAS_9.0 工程架构与数据流说明

## 1. 项目定位
该工程是一个基于 Qt6 的 DAS 实时处理与显示系统，核心职责是：
- 通过 PCIe 采集原始数据。
- 完成重构、相位解缠、滤波、RMS/FFT 等计算。
- 实时显示音频曲线、RMS 瀑布、频谱瀑布/频谱图（可切换）、光强图。
- 按需保存全量/单点数据。

## 2. 最关键结论（给开发者）
整个工程处理链路中最重要的“统一数据形态”是：
- `float*` 表示的二维相位数据数组（逻辑上是 `float[rows][cols]`）。
- 该二维相位数组在 `rebuild_data -> unwrap -> Filter -> rms_calculate / fft / UI / 保存` 全链路中传递。

简化理解：
- `rows`：空间通道（位置点/监测点）。
- `cols`：单帧内时间采样点（当前代码典型为 `5000`）。

## 4. 主流程说明（按执行顺序）
1. `main.cpp` 创建线程与模块对象，连接信号槽，启动处理线程。
2. `receive_data.cpp` 轮询 PCIe，按模式读取 DMA 数据并发射 `Raw_data(...)`。
3. `rebuild_data.cpp` 将原始字节流转为 `float`，做差分、抽取、转置后输出二维相位数组。
4. `unwrap.cpp` 对二维相位数组执行解缠（含跨帧记忆）。
5. `Filter.cpp` 可选高通滤波，同时提取音频监测通道 1~2 行数据。
6. 分支计算/展示：
- `rms_calculate.cpp` 计算 RMS，送 UI 瀑布图。
- `fft_calculate.cpp` 计算 FFT，送频谱瀑布；UI 可切换为频谱线图显示。
- `audio.cpp` 音频播放。
- `MainWindowData.cpp` 完成音频/瀑布图实际渲染。
7. UI 侧两个音频图共享 X 轴时间范围（便于横向对比），Y 轴各自按波形自适应。
8. `sava_data.cpp` 按 UI 命令保存全量或单点数据。

## 5. 各 cpp 文件职责总览
### 核心业务
- `main.cpp`：程序入口、线程创建、模块连接、生命周期管理。
- `receive_data.cpp`：PCIe 读取与采样参数驱动。
- `rebuild_data.cpp`：原始字节重构为二维相位数组。
- `unwrap.cpp`：相位解缠。
- `Filter.cpp`：高通滤波、音频行抽取、应变分支数据生成。
- `rms_calculate.cpp`：RMS 计算。
- `fft_calculate.cpp`：FFT 计算。
- `audio.cpp`：实时音频输出。
- `sava_data.cpp`：数据保存与磁盘空间校验。

### UI 与渲染
- `mainwindow.cpp`：主界面、参数交互、音频通道面板、业务槽函数。
- `mainwindowdata.cpp`：音频/RMS/FFT 图数据渲染。
- `mainwindowplot.cpp`：图表初始化与样式。
- `mainwindowutils.cpp`：UI 辅助计算（耗时阈值、X 轴范围等）。

### 参数与工具
- `parametermanager.cpp`：线程安全参数单例与广播。
- `toolutils.cpp`：通用工具函数（旧工具集，当前主流程使用较少）。

### 兼容/历史或第三方
- `mainwindowinteraction.cpp`：旧交互层（当前逻辑已大部分整合到 `mainwindow.cpp`）。
- `plotinitializer.cpp`：旧版图表初始化工具（当前主要使用 `mainwindowplot.cpp`）。
- `pcie_fun.c`：PCIe 驱动层接口封装（Win32 + XDMA）。
- `my.cu`：CUDA 示例计算（当前主流程未使用）。
- `qcustomplot.cpp`：第三方绘图库源码。

## 6. 开发时应优先记住的接口
- 上游统一输出：`widget_my_array_Signal(float* array, int rows, int cols, ...)`
- 解缠后统一输出：`Unwrap_Data_Signal(float* array, int rows, int cols, ...)`
- 滤波后统一输出：`Filter_my_array_Signal(float* array, int rows, int cols, ...)`

这三个信号都围绕同一个核心实体：**二维相位数据数组**。
